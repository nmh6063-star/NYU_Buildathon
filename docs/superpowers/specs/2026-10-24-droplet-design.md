# Droplet — Design Spec

**Date:** 2026-10-24
**Status:** Approved in chat. Waiting for review of this written spec.

Droplet is a native iOS app. It links a bank through Plaid, rounds every settled card purchase up to the next dollar, and banks the change as "drops". When the drops reach a threshold, it invests them automatically in a crypto asset the user chooses, priced from True Markets.

## 1. Decisions (locked)

| Topic | Decision | Why |
|---|---|---|
| Investing rail | True Markets, **crypto only** | True Markets sells tokenized stocks, but `GET /v1/gateway/assets/availability` from the US returns `allowed_asset_classes: ["crypto"]`. Stock orders get `403`. |
| Trade execution | **Simulated only** in this build | True Markets production has no test mode; every order is a real on-chain trade. Simulated fills use the live public True Markets price. Live orders are a future addition behind the same interface. The True Markets private key is **not used** in this build. |
| Bank data | Plaid **Sandbox** | Free and unlimited. `/sandbox/transactions/create` lets us stage exact demo purchases. |
| Backend | Supabase: Auth, Postgres with RLS, Edge Functions (Deno/TS), pg_cron with pg_net | Keeps the Plaid secret and access tokens on the server. Gives us webhooks and scheduled sync. |
| Auth | Supabase email + password, email confirmation **off** | The demo runs in the Simulator only. Sign in with Apple needs a paid developer account. |
| iOS | SwiftUI, deployment target **iOS 26.0**, Xcode 27.1, Swift 6, project generated by **XcodeGen** | iOS 26 gives the native Liquid Glass floating tab bar. |
| Navbar | **Native `TabView`** (floating glass capsule) plus `tabViewBottomAccessory` "next drop" pill | Picked in chat over custom circles. |
| Default threshold | **$5.00** (options $2, $5, $10) | True Markets minimum notional is about $1. The docs' examples use $2. Acorns and Stash use $5. |
| Assets | Curated: SOL, ETH, CBBTC, AAVE, JUP, RENDER. Default **SOL** | The full catalog has 219 listings, mostly meme coins. |

### Non-goals (this build)
- Real True Markets orders, wallet funding, ACH debits.
- Sign in with Apple, push notifications, multiple banks per user, round-up multipliers.
- Live portfolio valuation or P&L. The Portfolio screen shows only the **amount invested** per asset.

## 3. Data model

All money is `bigint` cents. Asset quantities are `numeric(38,18)` and are serialized to the client as strings.

```sql
-- public.profiles  (1 row per auth user, created by trigger on auth.users insert)
id uuid pk references auth.users on delete cascade
display_name text not null default ''
threshold_cents int not null default 500 check (threshold_cents in (200,500,1000))
target_asset text not null default 'SOL' references public.assets(symbol)
roundups_paused boolean not null default false
created_at timestamptz not null default now()

-- public.assets  (curated, seeded; read-only to clients)
symbol text pk, name text, chain text, tm_asset_id uuid, icon_url text, sort_order int, enabled boolean

-- app_private.plaid_items  (NO client access: schema not exposed, RLS on, no policies)
id uuid pk, user_id uuid unique references auth.users on delete cascade
item_id text unique not null, access_token text not null, cursor text
institution_name text, status text not null default 'active'   -- active | login_required | error
created_at, updated_at

-- public.bank_connections  (client-safe mirror: no token)
user_id uuid pk, institution_name text, status text, last_synced_at timestamptz

-- public.transactions
id uuid pk default gen_random_uuid()
user_id uuid not null references auth.users on delete cascade
plaid_transaction_id text unique not null
merchant_name text not null, amount_cents bigint not null  -- positive = money out
iso_currency_code text not null default 'USD'
date date not null, pending boolean not null, category text
roundup_cents int not null default 0 check (roundup_cents between 0 and 99)
roundup_status text not null  -- pending | invested | skipped | reversed
investment_id uuid null references public.investments(id)
created_at timestamptz not null default now()

-- public.investments
id uuid pk, user_id uuid not null
asset_symbol text not null references public.assets(symbol)
amount_cents bigint not null check (amount_cents > 0)
price_usd numeric(38,18) not null, quantity numeric(38,18) not null
mode text not null default 'simulated'  -- simulated | live (future)
status text not null default 'filled', tm_order_id text null
created_at timestamptz not null default now()

-- public.portfolio_by_asset  (view, security_invoker = true)
user_id, asset_symbol, asset_name, icon_url, invested_cents (sum), quantity (sum), last_invested_at

-- public.drop_summary  (view, security_invoker = true)
user_id, pending_cents, threshold_cents, lifetime_roundup_cents, invested_cents
```

**RLS:**
- Every public table has RLS enabled.
- `authenticated` gets `select` on its own rows (`(select auth.uid()) = user_id`, or `= id` for profiles) and on `assets`.
- `update` on `profiles` only for `display_name`, `threshold_cents`, `target_asset` and `roundups_paused`.
- Clients **never** insert into `transactions` or `investments`. Only Edge Functions (service role) write them.
- `app_private` is not in the exposed PostgREST schemas.

## 4. Round-up and invest rules

### 4.1 Round-up (pure function, `_shared/roundup.ts`, mirrored in Swift for display only)
```
roundupCents(amountCents) = amountCents <= 0 ? 0 : (100 - amountCents % 100) % 100
```
A transaction is **eligible** when all of these hold:
- `amount_cents > 0`
- `pending == false`
- `iso_currency_code == 'USD'`
- `personal_finance_category.primary` is not one of `TRANSFER_IN`, `TRANSFER_OUT`, `LOAN_PAYMENTS`, `BANK_FEES`, `INCOME`

Statuses:
- Eligible with `roundup > 0` → `pending`.
- Eligible with `roundup == 0` (whole dollar), or not eligible → `skipped`.
- Pending (unsettled) Plaid transactions are stored as `skipped` with `pending = true`. When Plaid posts them, the posted transaction arrives as a new `added` row and the pending ID shows up in `removed`.

### 4.2 Sync (`plaid-sync`, `_shared/plaid.ts`)
1. Load the user's `plaid_items` row.
2. Loop `/transactions/sync` with the stored cursor (`count: 500`) until `has_more == false`. On `TRANSACTIONS_SYNC_MUTATION_DURING_PAGINATION`, restart from the cursor this run began with.
3. `added` and `modified`: upsert on `plaid_transaction_id` and recompute the round-up. A row already `invested` keeps its round-up and status unchanged.
4. `removed`:
   - If the round-up is `pending` or `skipped`, set it to `reversed` with `roundup_cents = 0`.
   - If it is `invested`, leave it alone (already spent).
5. Save `next_cursor` and update `bank_connections.last_synced_at`.
6. Call **sweep**.

Plaid errors:
- `ITEM_LOGIN_REQUIRED` → `status = 'login_required'`, so the app shows Reconnect.
- Other errors → `status = 'error'`, and the function returns `502` with `{code, message}`.

### 4.3 Sweep (atomic, Postgres function `public.sweep_drops(p_user uuid, p_price numeric)`, `security definer`, executable only by `service_role`)
1. Lock the profile with `select ... for update`. If `roundups_paused`, return null.
2. `pending = sum(roundup_cents)` over `pending` rows. If `pending < threshold_cents`, return null.
3. Insert into `investments`: `amount_cents = pending`, `price_usd = p_price`, `quantity = pending / 100.0 / p_price`, `mode = 'simulated'`.
4. Update those transactions: `roundup_status = 'invested'`, `investment_id = new.id`.
5. Return the investment row.

The Edge Function gets the price **before** calling the RPC:
- Source: `GET https://api.truemarkets.co/v1/defi/market/prices?symbol=<SYM>`, using the `30s` candle `closePrice`, with a 5 s timeout.
- If the price fetch fails, skip the sweep. The drops stay pending, and the next sync retries.
- The whole pending amount is invested, not just the threshold amount.

## 5. Edge Functions (contracts)

| Function | Auth | Request | Response |
|---|---|---|---|
| `plaid-link-token` | user JWT | `{}` | `{ link_token, expiration }`. Calls `/link/token/create` with `products:["transactions"]`, `country_codes:["US"]`, `client_user_id = user.id`, `webhook = PLAID_WEBHOOK_URL`, `transactions.days_requested = 30`. |
| `plaid-exchange` | user JWT | `{ public_token, institution_name }` | `{ ok: true, synced: n }`. Exchanges the token, upserts `plaid_items` and `bank_connections`, runs sync. |
| `plaid-sync` | user JWT | `{}` | `{ added, modified, removed, investment: Investment \| null }` |
| `plaid-webhook` | none (`verify_jwt=false`), verifies `Plaid-Verification` ES256 JWT | Plaid payload | `200`. On `TRANSACTIONS / SYNC_UPDATES_AVAILABLE`, syncs the matching item. |
| `sync-all` | secret key (`verify_jwt=false`, checks `apikey` == service key) | `{}` | Syncs all `active` items. Called by pg_cron every 15 min. |
| `simulate-purchase` | user JWT, only when `PLAID_ENV=sandbox` | `{ merchant, amount_cents }` | Calls `/sandbox/transactions/create` (posted today; works on any Sandbox item, and the rows appear on the next `/transactions/sync`), then sync. Returns the sync result. |

Shared behavior:
- CORS is not needed, since only the native client calls these.
- Errors: JSON `{ error: { code, message } }` with the right 4xx/5xx status.
- Every function logs `user_id`, the Plaid `request_id`, and counts, never tokens.

## 6. iOS app

### 6.1 Structure and state
- **State container:** `@Observable` `AppModel`, owned by `DropletApp`.
  - Auth state comes from `supabase.auth.authStateChanges`.
  - Routing: `.signedOut → AuthView`, `.needsBank → ConnectBankView`, `.ready → MainTabs`.
- **API layer:** a `DropletAPI` protocol with `LiveDropletAPI` (Supabase) and `PreviewDropletAPI` (in-memory fixtures for previews and tests). Feature models take the protocol.
- **Shared summary:** `MainTabs` owns one `DropSummary`, refreshed on appear, on pull-to-refresh, after a simulated purchase, and when the app returns to the foreground.

```swift

  func signIn(email: String, password: String) async throws

  func updateProfile(_ patch: ProfilePatch) async throws -> Profile
  func assets() async throws -> [Asset]
  func bankConnection() async throws -> BankConnection?
  func createLinkToken() async throws -> String

  func simulatePurchase(merchant: String, amountCents: Int) async throws -> SyncResult

}
```

### 6.3 Design system (`Design/Theme.swift`, per the emilkowalski apple-design guide)
- **Typography:** SF Pro (system) only. Hero numbers 56pt semibold, tracking −1.1, `monospacedDigit`. Titles use `.largeTitle` and `.title2`, body uses `.body`. Respect Dynamic Type.
- **Color:**
  - Mostly monochrome, plus one accent: `Droplet` blue `#2F7BF6` light / `#5A9BFF` dark, used for round-up amounts, the gauge fill and selection.
  - Semantic `.primary`, `.secondary` and `.tertiary` for text. Grouped backgrounds come from the system.
- **Motion:**
  - Springs only: `Theme.spring = .spring(response: 0.4, dampingFraction: 1.0)`, and `.spring(response: 0.3, dampingFraction: 0.8)` for sheets.
  - Buttons scale to 0.97 on press-down.
  - Under `accessibilityReduceMotion`, use cross-fades only.
- **Materials:** glass only on chrome (tab bar, accessory, floating buttons), never on content cards. Cards use `.background(.background.secondary, in: .rect(cornerRadius: 24))`. Use scroll edge effects instead of dividers.
- **Haptics:** `.sensoryFeedback(.success)` when a sync returns an investment, `.error` on failures, `.selection` on picker changes. Nothing per round-up.

## 7. Error handling
- **App:**
  - Each feature model exposes `error: UserFacingError?`, which renders as an inline glass banner with Retry.
  - `FunctionsError.httpError` is decoded into `{code, message}`.
  - Network loss shows "You're offline". Previously loaded data stays visible.
- **Plaid:**
  - `login_required` surfaces in Profile and as a banner on Spending.
  - Link `onExit` with an error shows that error's display message.
- **Sweep:** idempotent under concurrency (row lock). The price fetch failing is non-fatal.
- **Webhook:**
  - Invalid signature → `401`.
  - Unknown item → `200` (no retry storm).
  - Signature checks:
    - `alg` must be ES256.
    - The JWK is fetched with `/webhook_verification_key/get` and cached in memory for each function instance.
    - `iat` must be within 5 minutes.
    - The raw body's SHA-256 must equal `request_body_sha256`.

## 8. Testing
- **Deno (`deno test supabase/functions/tests`):**
  - `roundupCents` table tests (5.67→33, 4.00→0, 0.01→99, −12.00→0).
  - Eligibility rules.
  - The sync merge reducer as a pure function over Plaid sync pages, covering pending→posted, removed after invested, and modified amount.
  - Price parsing.
  - Webhook verification with a locally generated ES256 key.
- **SQL:** sweep behavior is checked against the database after migrations:
  - Under the threshold → null.
  - At the threshold → one investment, and its rows are marked `invested`.
  - Paused → null.
  - Two concurrent calls → exactly one investment.
- **Swift Testing (`xcodebuild test`):** `Money` formatting and round-up mirror, `Transaction` and `Investment` decoding (string numerics), and the feature models against `PreviewDropletAPI` (summary math, error mapping, routing).
- **End to end in the iPhone 17 Simulator:**
  1. Sign up.
  2. Connect the sandbox bank (`user_good`).
  3. Add a test purchase of $5.67 → +$0.33 pending.
  4. Add purchases until past $5 → an investment appears in Portfolio with the SOL price.
  5. Take screenshots of each tab.

## 9. Setup steps that need the user
1. Authenticate the Supabase MCP and Plaid MCP servers (OAuth) that `.mcp.json` registers. Then create or choose a Supabase project (free tier).
2. Confirm that the Plaid secret is a **Sandbox** secret. A test `/link/token/create` against `sandbox.plaid.com` checks this. If it is not, copy the Sandbox secret from the Plaid Dashboard.
3. In Supabase Auth settings, turn off "Confirm email" so sign-up works instantly in the demo.

## 10. Future (out of scope)
- Live True Markets orders:
  - Mint a token with ES256 r‖s over `{key_id}.{timestamp}`.
  - `POST /v1/gateway/orders` with `qty_unit:"quote"`.
  - Stamp the returned `payloads` with DER-hex signatures, then execute and poll status.
  - Do all of this in an Edge Function behind `mode = 'live'`.
- Gateway multi-user wallets, USDC funding and on-ramps, Sign in with Apple, push notifications on each drop.
